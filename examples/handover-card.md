# 一屏分享卡与任务交接单

**虚构演示，非实际人员测量。**沿用[交付型产品经理案例](product-manager-delivery.md)：固定周报在虚构设定中连续六周通过验收，PRD 仍只具备试岗条件。以下不是企业已作出减编决定的通知。

```text
【取代倒计时｜虚构演示】产品经理 · 2026-10-23
你这周报就是 AI 的活儿，赶紧写交接文档吧。
凭什么：设定中已连续六周过验收；PRD 还没拿到这张证。
下一个试岗：标准 PRD 草案，先连续四周过验收。
规划窗口：3–6 个月，前提是资料接入获批、验收达标；整岗时间未知。
你还得干：取舍需求、处理上线异常，别只负责把文档写长。
本月：周报列交接单；20 份样本试 PRD，复核返工都计时。
情景分析，非失业预测。
```

“赶紧交接”得有东西可交。固定周报在本例中的任务交接单如下，只用于明确分工；实际切换仍由授权负责人决定。

| 交接项 | 写清什么 |
| --- | --- |
| 输入 | 仅使用批准的数据源、固定指标口径与模板；数据缺失时不能编数 |
| 验收 | 业务负责人按原模板和既有质量规则验收；六周记录只支持这个固定流程 |
| 异常回退 | 数据缺失、口径变更、校验失败时停止自动交付，转回人工处理并留下记录 |
| 人工负责人 | 产品负责人确认口径及最终交付责任；指标异常由对应业务角色解释 |

标准 PRD 尚无同等证据：应给它试岗清单，先做样本和验收，不能把“候选任务”写成“已经交权”。
